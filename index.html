03 / research

Featured findings

SSRF

A public fetcher that crossed the trust boundary

Private programme · Web / Infrastructure

A public URL-fetching endpoint accepted an arbitrary address and requested it server-side, unauthenticated — from inside the organization's network. The application itself was the proxy.

That one endpoint exposed several internal-facing services to the internet, including an unauthenticated Apache Solr admin instance. The interesting part was the chain it enabled, not just the reachability.

internet→ public URL fetcher→ internal network→ Solr admin (no auth)→ RCE chain potential
  • Full internal reachability from a single public request
  • Unauthenticated admin surface exposed (Solr)
  • Chain potential to template injection (CVE-2019-17558) under the right config

Validated strictly through the public endpoint — internal infrastructure was never contacted directly. The impact path was demonstrated without destructive steps, and the report closed through the programme's official channel.

XSS ×6

One template, three environments, six reflection points

HackerOne private programme

A JSP template interpolated two parameters directly into an HTML attribute with no output encoding. Not a framework bug — a plain <%= … %> hand-rolled into the markup.

Because two parameters were affected and the same template shipped to Production, Dev, and Staging, the root cause reproduced six times. One finding, six reflection points.

  • Attribute-breakout payload executes with zero interaction
  • Cookie read confirmed (JSESSIONID) unless HttpOnly is set
  • Deterministic PoC supplied — exact URL, encoded payload, evidence

Triaged on HackerOne; assessed as a duplicate of an earlier report. The lesson stuck: search prior art before deploying a cycle.
